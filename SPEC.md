# Agent and AI harness — spec

Status: **approved** by the user in chat on 2026-11-21, spec revision 2.

## System and revision

**Operating goal.** Give DynamicShopper a bounded AI agent and the harness around it, so that a shopper's chat message, interview answer or in-session behaviour can reshape the store's presentation (theme, layout, density, language, card details, ranking priorities, filters, page sections) while no fact (price, rating, specs, vouchers, deal totals) can be changed, invented or leaked by the AI. The harness is UI-agnostic: it exposes pure TypeScript functions and one local endpoint that the UX preset Codex is designing (branch `codex/shopee-adaptive-ux-draft`) can call without knowing about the model.

**Code revisions.** Base `main` @ `6c8c3da`. Catalog and pricing types come from `origin/feat/catalog-pricing` @ `1d0dab4` (not yet on main), merged locally. UX contract reference: `origin/codex/shopee-adaptive-ux-draft` @ `763863f`.

**In scope (this draft).**

1. Plan model: allowlisted parts, part-by-part validation, merge, undo/reset, signal precedence, "What changed" diff (bilingual, computed, never AI-written).
2. Deterministic ranking with explanation terms.
3. Offline keyword interpreter (Thai, English, mixed) producing the same `Turn` shape as the AI.
4. Turn pipeline: understand → validate → guard → interpret → price → apply → rank, as one pure `handleTurn` call.
5. Bounded agent: an OpenAI model (id from `OPENAI_MODEL`, key from `OPENAI_API_KEY`) called through the official `openai` package behind a `ModelTransport` interface, in a manual loop with two read-only tools, hard round/time/size limits, price-free projection, and fallback on every failure.
6. Local endpoint `POST /api/assistant`, present only in `dev` and `preview` builds.
7. X-ray trace: closed, allowlisted projection of what happened.
8. Poisoned-model simulation (development only).
9. Golden-set accuracy harness for both backends.
10. Adaptive-signal intake for Codex's learning flow: interview answers apply as explicit changes; session behaviour only ever becomes a **suggestion** the shopper taps to apply.
11. A ready-to-paste Codex task prompt for the next step: wiring this harness into Codex's UX preset.

**Excluded.** Any Svelte UI, components, styles or copy layout (Codex does this next, from the prompt in item 11). Checkout, payment, cart mutation by the agent. Cross-device sync or a database. Real Shopee data or marks, and live fetching from shopee.co.th (simulated catalog; real listings can be swapped in later as a data change once the team updates the guidelines). Public deployment of the model endpoint. Changes to the optimizer or catalog values (Owner 1 owns them).

**Delivery order.** This spec is implemented first on local branch `feat/agent-harness` (Owner 2's scope and planned paths: `src/lib/personalization`, `src/lib/server/agent`, `src/routes/api/assistant/+server.ts`), built on a local merge of `origin/feat/catalog-pricing`. Then Codex wires it into the UI from the handoff prompt. Nothing is pushed and nothing is committed by the implementer: per the user (2026-11-21), changes stay uncommitted on the local branch for the user to commit under their own name, with no co-author attribution.

**Dependencies added.** `openai` (official SDK: typed errors, request types; `maxRetries: 0` so the time limits stay honest). `zod` as a direct dependency (already present transitively; `AGENTS.md` requires Zod for request bodies).

## Contract

### Inputs and units

| Input                 | Type / unit                                 | Bounds                            | Invalid input behaviour                                                                                |
| --------------------- | ------------------------------------------- | --------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Shopper message       | UTF-8 string, NFC-normalised                | 1–500 chars after trim            | Empty → chat intent with help template. Over 500 → endpoint 413; client never sends.                   |
| History               | last turns `{role, text}`                   | ≤ 6 turns, each ≤ 500 chars       | Extra turns dropped oldest-first; failed turns are never sent.                                         |
| Plan                  | `Plan` (see PERSONALIZATION.md)             | allowlisted values only           | Validated part by part; bad part → default for that part.                                              |
| Focus / cart / viewed | catalog product ids                         | focus ≤ 3, cart ≤ 20, viewed ≤ 20 | Unknown ids dropped.                                                                                   |
| Budget                | whole baht, integer ≥ 1                     | parsed locally only               | Non-integer floored; < 1 dropped. Never sent to the model.                                             |
| Ranking weights       | number                                      | 0–1                               | Clamped. Model sends enumerated levels (`none/low/medium/high`) mapped locally to 0 / 0.33 / 0.66 / 1. |
| Behaviour signal      | `{kind, target, at}`; `at` ms epoch         | kinds from a closed list          | Unknown kind ignored.                                                                                  |
| Interview answer      | `{question, choice}`                        | closed lists from Codex's A2      | Unknown → ignored.                                                                                     |
| Clock                 | ms epoch, injected                          | —                                 | Tests use a fake clock.                                                                                |
| Money (outputs)       | whole baht integers from the optimizer only | —                                 | The harness never computes money.                                                                      |

### Outputs

`handleTurn(state, input, deps) → { state, turn, whatChanged, ranked, trace }`

- `turn`: intent-discriminated union: `restyle | search | persona` (carry a validated `PlanPatch`), `ask` (carries `citations: {productId, kind: spec|review|summary, key}`), `deal` (carries `basket: productId[]`), `undo | reset` (store commands, no patch), `chat`, `suggest` (carries a `PlanPatch` the shopper may apply). Every turn has `reply: {lang, text}` that has passed the guard, and `backend: 'model' | 'offline'` with `fallbackReason?`.
- `whatChanged`: list of `{part, from, to}` with localized labels from fixed templates; empty when nothing changed.
- `ranked`: `RankedProduct[]` with `terms: {label, contribution}` from the same computation as the order.
- `trace`: X-ray projection, closed schema (see R11).

### State

`StoreState = { plan, explicit: Set<PlanPart>, undo: Plan[] (≤ 20), focus, cart, viewed, lastTurn, suggestions }`. Initial state: the standard plan, empty everything.

### State table (store)

| Source | Event                                           | Guard                                               | Update                                                                                                                 | Destination          |
| ------ | ----------------------------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | -------------------- |
| any    | patch P (chat / interview / link / persona)     | `validate(P)` non-empty and `merge(plan, P) ≠ plan` | push plan to undo (cap 20, drop oldest); plan := merge; record diff; parts from an explicit source added to `explicit` | changed              |
| any    | patch P                                         | merged plan = plan                                  | nothing; empty diff; no undo entry                                                                                     | unchanged            |
| any    | inferred patch P (model / offline / suggestion) | touches a part in `explicit`                        | that part dropped with code `explicit_wins`; rest applies                                                              | changed or unchanged |
| any    | direct control C                                | —                                                   | applied as explicit patch                                                                                              | changed or unchanged |
| any    | undo                                            | undo non-empty                                      | plan := pop; `explicit` restored to its snapshot                                                                       | changed              |
| any    | undo                                            | undo empty                                          | nothing                                                                                                                | unchanged            |
| any    | reset                                           | plan ≠ standard                                     | push plan; plan := standard; `explicit` cleared                                                                        | changed              |
| any    | reset                                           | plan = standard                                     | nothing                                                                                                                | unchanged            |
| any    | ask / chat / deal turn                          | —                                                   | plan, explicit, undo untouched; focus may update                                                                       | unchanged            |
| any    | behaviour signal                                | —                                                   | may add or refresh a suggestion; plan untouched                                                                        | unchanged            |

### State table (agent loop)

| Source      | Event                                                                                            | Guard                                                      | Update                                        | Destination                           |
| ----------- | ------------------------------------------------------------------------------------------------ | ---------------------------------------------------------- | --------------------------------------------- | ------------------------------------- |
| start       | request accepted                                                                                 | no `OPENAI_API_KEY` or no `OPENAI_MODEL`, or force offline | —                                             | fallback(`no_key` / `forced_offline`) |
| start       | request accepted                                                                                 | poisoned armed (dev only)                                  | hostile envelope injected as the model output | validating                            |
| start       | request accepted                                                                                 | key present                                                | t0 := now; round := 0                         | calling                               |
| calling     | model returns `tool_use`                                                                         | round < 3 and now − t0 < 12000                             | run tools (pure, read-only), round += 1       | calling                               |
| calling     | model returns `tool_use`                                                                         | round = 3                                                  | —                                             | fallback(`too_many_rounds`)           |
| calling     | model returns proposal                                                                           | parses as envelope                                         | —                                             | validating                            |
| calling     | per-call timeout, overall deadline, API error, model refusal, output length cut-off, unparseable | —                                                          | —                                             | fallback(reason)                      |
| validating  | —                                                                                                | —                                                          | part-wise validation, guard                   | done(model)                           |
| fallback(r) | —                                                                                                | —                                                          | `interpretOffline`                            | done(offline, r)                      |

**Clock.** Origin: endpoint accepts the request (after size and shape checks). Per-call timer (6000 ms) starts when each request is sent and is enforced with `AbortController`. Overall deadline 12000 ms. Deadlines are exclusive: elapsed ≥ limit is late. Simultaneous: if a response and a deadline land in the same tick, the deadline wins. The per-call timeout is also clipped to the time left before the overall deadline.

**Model output shape.** The final answer is a JSON envelope `{intent, patch?, citations?, productIds?, reply}` requested via structured output and then validated locally with Zod, part by part. The model never chooses levels as numbers: priorities are `none | low | medium | high`.

**Formal model.** The skill asks for a model where a claim needs one. Two claims are checked by bounded exhaustive exploration written as Vitest tests over the real code (no separate model, so there is no model-to-code mapping gap):

- _Store (R2, R3):_ finite transition system over 12 events (inferred theme / language / mom persona / category / empty patch; explicit theme / language / category / search words; undo; reset; remove chip). All 12 + 12² + 12³ + 12⁴ = **22,620** transitions from the standard store to depth 4 are executed and checked: plan validity, undo cap, one undo step per effective change, none for a no-op, `undo ∘ change = id` on plan and explicit set (> 1,000 round-trips), reset semantics, and that inference never changes an explicit part or the explicit set. Reachability: every event is observed both changing and not changing the plan (except the empty patch, which can only be a no-op), and `explicit_wins` blocks are observed. Bound: depth 4 and this event alphabet; not a proof for longer sequences or other patches (the property test in R1 covers random patches).
- _Signals (R16):_ all 4⁶ = 4,096 sequences of 6 behaviour signals (three real kinds plus a junk kind): the plan never changes and no undo step is recorded; suggestions are observed.
- _Timing (R9):_ not modelled as timed automata. Instead each limit is executed with fake timers at the boundary and one below it: per-call answer at 5,999 ms accepted, at 6,000 ms late; overall answer at 11,999 ms accepted, at 12,000 ms late; never-resolving call cut at exactly 6,000 ms; a hang after two rounds cut by the overall deadline. Abstraction: the fake clock advances only through timers, so tool execution takes 0 ms in these tests.
