# Owner 2 · Personalization and agent implementation plan

**Goal.** A shopper can compare rice-cooker specs or request a readable Thai shortlist, undo an effective change, get a cited answer and request the shared cooker's deal, including with the network disconnected.

**Owner and consumers.** Owner 2 implements on their own working branch. Owner 3 imports the pure TypeScript engine into the SvelteKit storefront. Owner 1 supplies immutable catalog records, numeric spec definitions and the optimizer. Owner 4 assembles shared types, example data, independent golden labels and release checks. Use Bun and the existing Vitest server project.

Read [the team design](../specs/2026-11-21-two-shopper-design.md), [AGENTS.md](../../../AGENTS.md), [product](../../../guidelines/PRODUCT.md), [system design](../../../guidelines/SYSTEM-DESIGN.md), [personalization](../../../guidelines/PERSONALIZATION.md), [trust](../../../guidelines/TRUST-AND-PROOF.md) and [journey](../../../guidelines/JOURNEY.md). Use the executing-plans skill during implementation.

**Review focus.** Check undo after a no-op, tied ranks, ambiguous quantities, an unresponsive model and fallback responses counted as AI runs in Tasks 2–6.
